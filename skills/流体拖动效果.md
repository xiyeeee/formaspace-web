# 鼠标虹彩流体拖尾 · AI 实现提示词

请在当前 React + TypeScript + Vite 项目中，实现一个鼠标驱动的虹彩流体效果。视觉参考附带截图 image(8).png，目标是接近 Lusion 风格的轻盈、透明、有惯性的彩色液体轨迹，不要求复刻其内部算法。

## 一、交付目标

先创建独立效果预览页 /effects/fluid-cursor，不改变现有登录页布局和业务。
如果项目没有路由，沿用现有页面组织方式提供独立预览入口，不为此重建工程。
最终效果封装为 FluidCursorBackground，可在后续登录页中复用。

本轮只实现这个效果，不接接口，不增加登录、上传等功能。
直接编写并运行代码，完成浏览器视觉检查，不只返回实现方案。

## 二、视觉目标

优先参考浅色截图，而不是默认深色高饱和流体 Demo：

- 背景为接近 #F1F2FA 的浅灰紫色。
- 鼠标移动后出现半透明的淡蓝、淡紫、浅粉色拖尾。
- 拖尾边缘有极细的暖白、浅金或粉色虹彩高光。
- 中心颜色轻薄，像透明液体、玻璃薄膜，不是一团浓墨。
- 轨迹有宽窄变化和柔和的弯曲，快速划动时拉成长带。
- 鼠标绕圈时可带出小旋涡，停止后仍有短暂惯性，随后自然淡出。
- 鼠标首次进入时不产生从屏幕原点飞来的长线。
- 静止时不持续喷色，不自动生成随机爆炸。
- 不出现跟随鼠标的实心圆球，不画一串 DOM 圆点，不用普通渐变圆加 CSS blur 假装流体。
- 不隐藏系统鼠标指针。

视觉重点依次是：流动连续性、透明感、柔和消散、边缘虹彩。
不要用强 Bloom 和过曝掩盖效果问题。初始效果必须足够明显可见，之后再降低强度，避免透明到看不见。

## 三、推荐技术路线

复用项目已有 Three.js / React Three Fiber；如未安装，只补齐实际需要且与现有 React 兼容的依赖。
也可用原生 WebGL2，但不要为了这个效果在项目中并存多套无关渲染库。

推荐在 GPU 上完成二维流体模拟：
1. 记录指针位置与位移，换算为归一化画布坐标。
2. 把指针运动作为局部速度注入 velocity 场，把浅色染料注入 dye 场。
3. 更新速度平流、旋度及适度涡量约束。
4. 计算散度，迭代压力，再减去压力梯度。
5. 用更新后的速度平流染料，并进行基于时间的衰减。
6. 在最终全屏 Shader 中呈现透明染料、边缘高光及受控色散。

velocity、pressure、dye 等需要反馈的量使用各自的 ping-pong render targets；禁止同时读写同一个纹理附件。
计算 pass 使用无色调映射、无显示颜色空间转换的数值纹理；颜色空间转换仅在最终显示阶段正确完成。
根据设备检测半浮点渲染与线性过滤能力，不能假设所有设备都支持相同格式。
压力求解与模拟边界使用一致约定，避免边缘能量异常或出现 NaN。

可以借鉴开源流体实现，但在使用前检查项目 LICENSE，保留必要版权说明，并说明复用来源。
参考：
https://github.com/PavelDoGreat/WebGL-Fluid-Simulation

不必强行从零重写完整求解器，但必须交付可维护的 TypeScript 封装，不能只注入一个无法销毁的全局脚本。

## 四、拖尾与色散渲染

流场模拟和最终着色分开：

- velocity 表示流向，dye 表示可视轨迹。
- 可由 dye 或辅助高度场梯度生成近似表面法线，用来形成柔和折射和边缘高光。
- RGB 色散对三个通道使用轻微不同的采样偏移，范围很小。
- 流体内部透明度低，轮廓局部略亮，不能出现粗糙硬边和等宽霓虹管。
- 对浅色背景，不能只使用加法混合，否则浅色染料容易变成一片白。
- 推荐在最终 pass 中将背景色与染料柔和混合，并用单独的边缘项增加虹彩。
- 没有背景纹理时，用着色与梯度营造液体感；不要声称实际折射了页面 DOM。
- 若后续要折射三维背景，需要明确传入其渲染纹理。普通独立 Canvas 无法直接采样任意 HTML 页面作为背景。

不要将“RGB 分离”直接作用于整张页面截图；本轮只影响流体视觉。

## 五、指针处理

- 使用 Pointer Events，保存状态到 ref 或渲染模块中，不逐帧触发 React setState。
- 注入力与速度相关，并对极端速度进行钳制。
- 对长距离移动按轨迹插值注入，避免快速移动时变成断续圆点。
- 用实际画布 boundingClientRect 换算坐标，正确处理 Y 翻转与宽高比。
- 首次 pointerenter、页面重新获得焦点后重置上一位置。
- pointerleave 后停止注入，保留已有流体自然衰减。
- 标签页恢复时限制 deltaTime，防止一次大时间步导致数值爆炸。
- 不要求鼠标按住才能出现效果，默认悬停移动即可。
- 点击输入框、按钮和文字选择不受影响。

## 六、参数建议

下面是调参起点，不是所有求解器通用的配置名或单位。请根据实际实现映射并说明：

| 参数 | 建议 |
| --- | --- |
| 模拟网格 | 桌面长边约 128～256，另一边按比例 |
| 染料纹理 | 桌面长边约 512～1024 |
| 压力迭代 | 约 12～20 次，按性能调整 |
| 轨迹淡出 | 约 1.5～3 秒逐渐不可见 |
| 指针影响半径 | 约画布短边的 2%～5% |
| 涡量 | 克制，能弯曲但不形成猛烈翻滚 |
| 色散位移 | 约 0.5～2 个 CSS 像素的观感起步 |
| DPR | 最大约 1.5 |
| 移动端 | 降低分辨率，或默认关闭指针效果 |

衰减必须独立于帧率，可使用 exp(-rate * dt) 形式。
对速度、时间步与纹理边界进行必要处理，避免出现黑块、闪屏和不稳定扩散。

## 八、图层与生命周期

背景 Canvas 使用合适的绝对或固定定位，pointer-events: none。
指针监听挂在清晰的宿主或 window，组件卸载后全部移除。
UI 层在 Canvas 上方，布局和交互不被遮挡。
场景尺寸取实际容器尺寸，使用 ResizeObserver 并清理，resize 后正确重建相关 render targets。

使用现有 R3F 渲染循环时，不再额外开一个重复的 requestAnimationFrame。
原生 WebGL / Three 渲染循环须在卸载时取消。
释放所有自建 geometry、material、texture、render target 和监听器。
React StrictMode 开发模式下重复挂载不会导致双动画、重复事件或资源泄漏。

页面隐藏时暂停，恢复时重置时间基准。
prefers-reduced-motion 开启时默认关闭连续流体运动。
WebGL 不支持或上下文丢失时回退为干净的浅色背景，不影响页面其余部分。
触摸设备不要阻止滚动，也不要 preventDefault 整页触摸事件。

## 九、验收场景

请实际打开浏览器并检查：

1. 缓慢移动：产生轻薄、连续、柔和的色彩拖尾。
2. 快速横划：形成连续长带，没有断点和飞线。
3. 连续绕圈：有小范围流转和弯曲，不变成大量彩色烟雾。
4. 停止移动：已有轨迹继续短暂流动，约数秒淡出。
5. 鼠标离开再进入：不从旧坐标拉出横跨屏幕的线。
6. 切到其他标签页再回来：不闪屏、不爆色。
7. 改变窗口尺寸：轨迹位置准确，比例不变形。
8. 点击页面上的输入和按钮：正常使用。
9. 减少动效或 WebGL 不可用：有可用回退。
10. 无控制台报错，无 NaN、黑块或持续堆积不消散。

至少检查 1440×900 与 390×844。
记录实际设备或浏览器的流畅度观察，不编造帧率数据。
运行项目已有 lint、TypeScript 与 build 检查，如实报告。
截图只能展示静态观感；如果条件允许，补一段短录屏说明拖尾运动效果。
