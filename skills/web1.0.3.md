# FormaSpace 登录页搭建文档

> 用途：直接交给 Cursor / Codex 等 AI 编程工具，在现有前端项目中实现登录页。
> 本轮只做页面与本地交互，不接入接口，不实现 JWT、验证码发送、账号存储或登录跳转。
> 产品名称：形境 · FormaSpace。设计稿中的“维境 / VISION 3D”统一替换为新品牌。

## 1. 设计依据与目标

参考 vision-3d-designs.zip 中：
01-推荐设计/03-登录页-沉浸点云版.png。

搭建一个有沉浸感的图片转 3D 产品入口：
深色背景 + 大幅立体点云环绕曲面 + 荧光黄绿点缀 + 右侧半透明登录面板。
左侧表达“图片成为三维形态”，右侧保证账号输入与登录操作清晰。
不是传统后台登录模板，不加入数据卡片、营销统计或与登录无关的导航。

先实现视觉完整、输入可用的登录页；粒子需要实际渲染和响应鼠标，不能直接把包含表单文字的整张设计图当页面背景。

## 2. 页面范围

本轮只实现 /login 页面及其视觉组件。

包含：
- 品牌标识与 FormaSpace 字标。
- 沉浸式粒子背景、局部荧光轮廓、鼠标轻微扰动。
- 左下角品牌文案和底部过程说明。
- 右侧账号密码表单。
- 密码显示与隐藏。
- 输入校验、错误态、按钮 loading 预览。
- 注册入口的展示。

不包含：
- 注册页面、短信或邮箱验证码登录、第三方登录、找回密码页面。
- 接口封装、token、鉴权守卫、登录成功后跳转。
- 上传与模型生成业务。

设计稿中的“验证码登录”“忘记密码”“返回首页”“用户协议”“隐私政策”没有本轮对应页面，不制作可点击却无结果的链接。
已存在有效路由时可以复用；不存在时省略。注册入口同理：有 /register 则链接，没有则展示“注册功能即将开放”的本地提示。
不要假装已实现账号能力。

## 3. 技术与实现约束

沿用现有 React + TypeScript + Vite 工程。
表单、按钮、输入框优先复用项目已有 shadcn/ui；布局与主题使用 Tailwind CSS。
粒子场景使用 Three.js + React Three Fiber，可按需使用 Drei。
图标优先 lucide-react。已有 React Hook Form + Zod 时复用，未安装时可用轻量本地状态完成本轮校验。
不要为单页引入额外状态库和动画库，不重建工程，不升级无关依赖。
检查现有 package.json 后再补齐缺少的依赖，Three Fiber 与 React 的版本必须兼容。

## 4. 桌面布局

### 顶部

距屏幕顶部约 32～40px、左右约 40～56px。
左上角：荧光黄绿几何标识 + “形境”，下一行小字 FORMA SPACE。
标识使用可维护的 SVG 或 CSS 几何图形，不用 emoji。
如现有品牌 Logo 已确定，直接复用。
右上角保持留白；只有已有首页时才放“返回首页”。

### 主体

页面最小高度 100svh，背景覆盖全屏。
视觉区约占宽度 64%，登录面板位于右侧约 32%，二者允许视觉叠加。
登录面板建议宽度 420～480px、右边距 40～64px，垂直居中。
在 1440×900 和 1920×1080 下都保持舒展，不机械拉伸固定设计稿尺寸。
表单面板应留出完整输入与错误提示空间；低矮窗口允许纵向滚动。

### 左下品牌文案

大标题：
“把灵感，
变成立体。”

字号使用 clamp，桌面约 64～88px，字重 650～750，行高约 1.1。
末尾句点或小圆点使用荧光黄绿。
辅助文案：“从一张图片，到可触碰的想象。”
辅助文案字号约 18～22px，颜色柔和，保持清晰对比。

### 底部

左下方可显示静态流程标签：
“图片 → 点云 → 三维模型”
配一个短荧光线段作为装饰，不显示假轮播分页或无法切换的 01/03 控件。
右下角可显示“© 2026 FormaSpace”。

## 5. 视觉规范

建议色值仅作起点，以实际渲染和参考图统一调整：

| 用途 | 建议 |
| --- | --- |
| 页面背景 | #111210 / #181916 |
| 主要文字 | #F5F3EB |
| 次要文字 | #B7B8AF |
| 品牌强调色 | #CBF53A |
| 面板背景 | rgba(34, 36, 31, 0.62) |
| 面板边框 | rgba(245, 243, 235, 0.24) |
| 输入框背景 | rgba(10, 12, 9, 0.2) |
| 粒子主色 | 暖白、浅米金，少量黄绿 |

登录面板圆角约 24～28px，内边距约 36～44px。
使用克制的 backdrop-blur、细边框和柔和阴影；提供不支持模糊时的实色回退。
避免过多发光描边、强烈彩虹渐变、整片高亮荧光背景。
字体用系统无衬线与中文字体栈，不依赖外网字体才能正确展示。
正文、错误文字、占位文字都保持可读对比。

## 6. 立体点云背景

### 形态

参照设计稿创建大幅扭转环绕曲面，像有厚度和深度的柔性环带。
它不是单纯的星空随机散点，也不是平面点阵或一个普通球体。
中心可有孔洞，环带横跨左侧与页面中间，边缘延伸到画面外。
通过曲面采样生成点的位置；将形状参数计算与每帧更新分开。
环带的局部边缘带少量黄绿点，主体以暖白点组成。
可增加极弱的透明曲面作为体积辅助，但点云仍为视觉主体。

### 动效

- 默认缓慢呼吸、流动或旋转，视觉平稳，不能快速自转。
- 鼠标移动时，背景有小幅视差；指针附近粒子轻微偏移后平滑归位。
- 指针影响在视觉区生效，进入表单时减弱或停止，避免影响输入。
- 鼠标离开窗口时渐渐归位。
- 动效不覆盖表单点击区域，不捕获表单的指针和滚动事件。
- 不设置自动镜头大幅移动，不闪烁，不用强光追着鼠标跑。
- 粒子效果是装饰视觉，不描述为真实 AI 建模进度。

### 性能与结构

使用一个或少量 Points + BufferGeometry；不要为每个粒子生成 React 组件。
初始化位置缓存，逐帧更新使用 useFrame / shader uniform，避免每帧 setState。
桌面可从约 12,000～20,000 点起步，移动端约 3,000～6,000 点；实际以流畅度调整。
限制 DPR，例如最大 1.5；不默认开启昂贵后期处理和阴影。
页面隐藏时暂停或显著降低更新频率，卸载时清理监听器与自建 GPU 资源。
通过 lazy + Suspense 按需加载场景，保证表单先可用。
提供 WebGL 初始化失败、上下文丢失时的静态装饰回退。
prefers-reduced-motion 下关闭扰动与持续运动，保留静态形态。
移动端可使用静态粒子视觉，不强制运行完整 GPU 动效。

### 不允许的简化

不要把整张设计稿截图铺成背景，再在原有表单上叠一层新表单。
不要用普通 CSS 星点冒充立体环带。
可以用纯净的静态背景资产作为降级，但其中不能有烧录的品牌文案和输入框。

## 7. 登录面板

面板内容顺序：

1. 黄绿小字：“START CREATING”。
2. 标题：“开始你的创作”。
3. 辅助说明：“登录形境，让灵感拥有形状。”
4. “密码登录”区域标题或单一模式说明，不制作假的双 Tab。
5. “用户名或邮箱”输入框。
6. “密码”输入框，右侧显示 / 隐藏按钮。
7. 表单级提示区域。
8. 荧光黄绿主按钮：“登录”，右侧可放简洁箭头。
9. 底部：“还没有账号？立即注册”。

输入框高度约 48～52px，圆角约 8～10px。
登录按钮高度约 50～54px，清晰的 hover、active、focus-visible 和 disabled 状态。
错误出现时面板不应大幅跳动，错误文案靠近对应字段。
注册入口不要抢过登录主按钮的视觉权重。

## 8. 本地交互与表单校验

账号：
- 必填，提交前去首尾空白。
- 可输入用户名或邮箱，不能一律要求邮箱格式。
- autocomplete="username"。

密码：
- 必填，不 trim。
- type="password"，支持按钮切换可见性。
- autocomplete="current-password"。
- 支持粘贴、密码管理器、Enter 提交。
- 本轮登录只校验非空，不套用注册时的密码强度规则。

空表单提交：
显示“请输入用户名或邮箱”“请输入密码”，焦点移到第一个错误字段。

有效表单提交：
- 本轮没有接口，不发送请求。
- 使用显式的本地演示提交处理函数，可短暂展示 loading，再显示中性提示：
  “页面演示完成，登录接口尚未接入。”
- 不提示登录成功，不创建 token，不保存密码，不跳转工作台。
- 提交过程中禁用按钮，防止重复点击；组件卸载时清理演示计时器。
- 不在 console、URL 或浏览器存储中写入账号密码。
- 页面上可用轻量辅助说明标注“当前为界面预览”。

密码显示按钮必须 type="button"，提供 aria-label 和状态说明。
输入框使用真实 label；校验错误通过 aria-describedby 关联，aria-invalid 反映状态。
表单消息使用适当的 live region，不让屏幕阅读器重复播报动效。

## 9. 响应式

| 宽度 | 行为 |
| --- | --- |
| ≥1280px | 全屏点云 + 左下文案 + 右侧悬浮面板 |
| 768～1279px | 缩小标题和边距，面板约 400px，避免背景抢占表单 |
| <768px | 单列结构，顶部品牌，简化视觉，表单优先；允许页面滚动 |
| 低高度窗口 | 减少上下留白，保留所有输入和按钮，可纵向滚动 |

至少检查 1440×900、1024×768、390×844、360×640。
移动端输入字号至少 16px，避免触发不必要的输入放大。
背景可固定，但内容层不能固定高度后裁掉注册入口。
软键盘出现后，输入框、错误提示和按钮仍可通过滚动访问。

## 10. 建议组件拆分

按现有项目结构调整，不强行搬移其他代码：

```text
src/features/auth/
├── pages/login-page.tsx
├── components/
│   ├── auth-brand.tsx
│   ├── auth-visual.tsx
│   ├── particle-scene.tsx
│   └── login-form.tsx
└── lib/
    └── particle-geometry.ts
```

- login-page：整体排版与响应式。
- auth-brand：可复用品牌标识。
- auth-visual：懒加载、静态回退和减少动效策略。
- particle-scene：场景、相机、渲染和指针交互。
- particle-geometry：环带几何采样，避免与表单代码混合。
- login-form：账号、密码、本地校验和演示提交。

通用 Button / Input 等从现有 components/ui 复用。
如果工程尚无 shadcn/ui，先按项目基础配置正确初始化，不写一套同名伪组件。
只修改本轮所需文件，保留已存在的首页和其他路由。

## 11. 验收

视觉：
- 品牌为形境 / FormaSpace。
- 点云有明确三维形态、深度与局部黄绿点缀，接近参考图气质。
- 表单清晰可读，背景不遮挡文案，桌面与小屏无横向溢出。
- 没有整张设计稿背景导致的重复表单或文字。

交互：
- 输入、Enter 提交、密码切换、空值提示正常。
- 演示提交不会真正登录，也不会产生网络请求。
- 鼠标轻微扰动可见，表单仍可正常点击。
- 键盘可完成全部操作，焦点样式可见。
- 减少动效、移动端和 WebGL 失败均有回退。

工程：
- 执行现有 lint、TypeScript 和 build 检查并记录真实结果。
- 检查控制台无报错；没有未清理的监听、重复 Canvas 或演示计时器。
- 浏览器检查桌面与手机尺寸，提供实现截图供审阅。
- 不宣称已完成接口联调。

## 12. 直接发给 AI 的提示词

请在当前 FormaSpace 前端工程中实现本文描述的登录页。

先检查现有代码、路由、依赖与全局样式，复用已有 React、TypeScript、Tailwind、shadcn/ui 配置。参考随附的“03-登录页-沉浸点云版.png”，将品牌统一为“形境 · FormaSpace”，实现深色沉浸背景、可轻微响应鼠标的三维点云环带，以及右侧半透明登录面板。

本轮只做 /login 和本地表单交互：账号密码输入、空值校验、密码显示切换、loading 演示及未接入接口提示。不要读取或接入鉴权接口，不实现注册页面、JWT、邮箱验证码、token 存储或登录成功跳转。注册等入口只有在现有路由可用时才导航，否则给出明确未开放提示或省略。

按本文完成响应式、键盘可访问性、减少动效和 WebGL 降级。表单必须先可用，粒子场景按需加载。不能把整张设计稿作为页面截图背景，不能用随机星空代替立体环带。保留其他页面和用户已有代码。

完成后运行现有 lint/build，检查桌面和移动端页面，输出修改文件列表、真实验证结果、实现截图和仍待完善的事项。
